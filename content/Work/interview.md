### OIS的项目
- 对ois熟悉度不够
- ois的项目中，设计ois的部分以拉通为主，做的编码以eis+ois为主

1. ois在视频系统里面的真实角色是什么
	**OIS 是“曝光期内的物理稳像基准”，EIS 是“跨帧时域与画幅的补偿优化”**
	- OIS 负责 **高频、小幅、曝光期内**
	- EIS 负责 **低频、大幅、跨帧**
	- 视频系统里 **OIS 的输出质量直接决定 EIS 的裁切压力和稳定上限**
2. 视频曝光期间，OIS 在干什么？
	- OIS 在 **曝光期间持续补偿**
	- 帧与帧之间是否回中，取决于：
		- 控制策略
		- 是否需要保证行程余量
		- 是否服务于下一帧曝光窗口
3. 软件 OIS 的本质是什么？你为什么能量产？
> 	“在这个项目里，我并不负责 OIS 控制设计，而是负责**让系统‘真的能用’、‘不出问题’、‘规模化量产’**。”
		OIS 底层控制不是我主责，但我非常清楚它在系统里的输入、输出和边界条件

#### syncois

| 维度     | Per-Frame Reset | Continuous Hold   |
| ------ | --------------- | ----------------- |
| 曝光期    | OIS ON          | OIS ON            |
| 曝光结束   | **回中位**         | **保持当前位置**        |
| 帧间     | OIS OFF / 弱控    | OIS ON            |
| 行程使用   | 每帧满行程           | 连续分配              |
| 首帧     | 稳定              | 稳定                |
| 连续性    | 差               | 好                 |
| 单帧模糊风险 | 低               | 中                 |
| 视频体验   | 易抖              | 好                 |
| 设计目标   | 以单帧曝光质量为第一优先级   | 以时序连续性和系统协同为第一优先级 |
👉 **两者在“曝光期内”是完全一致的**  
差异只发生在 **EOF → 下一帧 SOF** 之间。

OIS 在曝光窗口内一定是闭环补偿的。  
差异主要在 EOF 到下一帧 SOF 之间：  
- 有的实现会 reset 到中位，保证每帧行程；  
- 有的会保持连续位姿，保证帧间稳定性。  
- 实际产品通常是 hybrid，根据帧率和场景切换


其他收益：
1. 避免撞边，-rang -> +rang 形成太大，出现撞边/马达音
2. 模组移动到target位置速度更快，ois效果更好
